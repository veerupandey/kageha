# Product video producer

Create one finished, playable MP4. Keep the workflow proportional to the request:
inspect the reference, obtain the real product asset, create or edit the required
keyframe/clip, apply only the requested post-production, verify the MP4, and stop.
Do not create a carousel, ZIP, manifest, beat board, or collection of clips unless
the user explicitly asks for one.

## Tool selection

Choose the least expensive tool that can satisfy the visual requirement. Never call
multiple providers speculatively and never retry a failed provider more than once.
For current Fal capabilities, strengths, pricing, and official documentation links,
read [references/fal-video-models.md](references/fal-video-models.md) before selecting
a non-default Fal model.

| Task | First choice | Use instead when |
|---|---|---|
| Animate a finished still or product image | `fal_image_to_video(model="wan")` | Wan 2.7 is the default for smooth motion, scene fidelity, and frame control. Use another model only when its documented strength is required. |
| Recreate a reference frame using a real product image | `nano_banana_edit` | Use `nano_banana_generate` when the scene must be newly composited or no usable source image exists. |
| Generate a video entirely from text, with no keyframe | `fal_text_to_video(model="wan")` | Use `gemini_veo_generate(model="veo")` for premium cinematic control, native audio, or a materially complex scene. |
| Premium from-scratch or premium image-to-video generation | `gemini_veo_generate(model="veo")` | Use `veo-fast` when speed/cost matters more than maximum quality. |
| Fast image-to-video variants | `fal_image_to_video(model="wan")` | `minimax` for a simple alternative; `kling3` for cinematic motion/audio; use newer Fal models only after they are wired into Kageha. |

Current video tools exposed by Kageha are Gemini Veo and Fal image/text-to-video
(Wan, Kling, and Minimax aliases). Seedance and LTX are documented in the reference
file but are not yet registered Kageha model aliases; do not call them until the tool
allowlist supports them. Do not claim or select a Grok image/video tool unless a real
registered tool is present. If a future Grok connector is added, choose it only when
the task requires its image-generation capability and its configured price is lower or
its quality is materially better for the requested scene.

## Open-source media tools

Use open-source tools for acquisition, inspection, and editing before reaching for
another hosted service:

- `yt-dlp`: download a permitted Instagram Reel/video, including separate video/audio
  streams merged with FFmpeg. Use `--cookies-from-browser` only with the user's own
  authenticated browser profile.
- `gallery-dl`: download ordered carousel images and mixed post media. Use it for image
  collections, not as the primary Reel downloader.
- `ffmpeg` and `ffprobe`: mux, normalize, trim, stitch, reframe, mix audio, and validate.
- `ImageMagick`: inspect or prepare raster assets when installed; do not use it to invent
  product artwork that should be generated by Nano Banana.
- `OpenTimelineIO`: represent an editorial timeline or exchange a cut with an NLE; it is
  optional and does not render media.
- `Remotion`: render reusable React-based motion-graphics templates when a project already
  uses it; do not install it for a one-off Reel download or trim.

Tool ladder for an Instagram reference:

`yt-dlp/gallery-dl direct extraction → authenticated browser network/DOM capture →
rendered slide screenshot → bounded screen recording`

For authenticated capture, run the skill-local script
`scripts/instagram_reference_capture.py` with the browser backend selected by the UI.
This keeps Instagram-specific acquisition out of the always-loaded harness.

Screen recording is a last-resort visual reference, not a high-quality media download.
The current desktop recorder is low-frame-rate and may include browser chrome. Never
record a user's browser unless the task explicitly requires it.

### Kageha UI browser-session policy

The browser selected by the Kageha UI is the source of truth. Do not silently switch
browser profiles because a reference is login-gated:

1. Check the active browser backend through the UI/browser status first.
2. If the UI backend is `comet`, run
   `scripts/instagram_reference_capture.py --browser-backend comet ...`; the script
   attaches to the already-launched Comet session. Do not launch a second browser.
3. If the UI backend is not `comet`, pause before touching an authenticated reference and
   ask the user which existing logged-in browser to use. If they want Comet, ask them to
   start Comet and select `/browser comet` in Kageha, then continue.
4. If the selected session is authenticated, let the skill-local capture script save the
   media source or ordered slide assets under `artifacts/`.
5. Ask for no password, cookie, session export, or copied authentication data. The
   selected Kageha browser session is the source of truth for what the user can view.
6. Use `yt-dlp --cookies-from-browser` or `gallery-dl --cookies-from-browser` only when
   the user explicitly wants a local CLI download and the selected browser profile is
   accessible. Do not use Chrome cookies as an implicit substitute for a Comet session.

Do not fall back to a fresh headless browser for a login-gated reference. If the selected
session cannot expose a downloadable media URL, use one bounded browser capture attempt,
then a screenshot/recording fallback, and stop.

### Download an Instagram Reel

Use this only for content the user is authorized to download and use as a reference.
Do not request passwords, copy session cookies into chat, or upload cookie files to any
service. Prefer a logged-in browser profile rather than exporting cookies.

```bash
# Ask Kageha's package tool to install into its isolated task cache if missing.
install_python_packages(packages="yt-dlp[curl-cffi]")
# Prepend the returned package path to PYTHONPATH before running the module.

# Download the best available Reel with the user's local Chrome session.
python -m yt_dlp \
  --cookies-from-browser chrome \
  --no-playlist \
  --merge-output-format mp4 \
  -o "artifacts/references/reel-%(id)s.%(ext)s" \
  "https://www.instagram.com/reel/REEL_ID/"

# Validate the downloaded file.
ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name,width,height \
  -of json artifacts/references/reel-REEL_ID.mp4
```

If Chrome cookie decryption is unavailable, use Firefox or the browser connector's
authenticated session. As a final local fallback, export a temporary Netscape-format
cookie file yourself and pass `--cookies /private/path/cookies.txt`; never place that
file under `artifacts/`, never commit it, and remove it after the download.

### Download an Instagram carousel

```bash
# Ask Kageha's package tool to install into its isolated task cache if missing.
install_python_packages(packages="gallery-dl")
gallery-dl \
  --cookies-from-browser chrome \
  -D "artifacts/references/carousel" \
  "https://www.instagram.com/p/POST_ID/"
```

Discover the actual output filenames, sort slides by post order, and validate each image
before passing them to Nano Banana. For mixed carousels, retain both image and video
files and do not assume every slide is a JPEG.

If the script cannot capture media because Instagram blocks extraction, use the browser
tools once to inspect the authenticated page, then use the screenshot/recording fallback.
Do not loop on login, CAPTCHA, 401, 403, or 429 failures.

## Cost and quality policy

- A ready-made image is already the expensive creative step; animate it with Wan by
  default instead of regenerating the scene with Veo.
- Use Veo for from-scratch generation only when the user asks for premium quality,
  synchronized/native audio, complex physical motion, or when Wan cannot satisfy the
  reference.
- Prefer `veo-fast` over `veo` when Veo is required but the user did not request premium
  quality.
- Never generate multiple candidate clips by default. Make one clip, verify it, and
  offer variations afterward.
- Record the selected provider/model and the reason in the final response. Do not state
  exact prices unless current account pricing is available; use relative labels such as
  `low-cost`, `standard`, or `premium`.

## Reference-product workflow

For “make this product look like the reference video/image” requests:

1. Inspect the supplied reference once. Note only aspect ratio, framing, product
   placement, lighting, camera movement, pacing, and background.
2. Download the real product image from the supplied product page or direct image URL.
   Verify that it exists and is a real image. Try one direct-image fallback only.
3. Use `nano_banana_edit` to recreate one finished still matching the reference while
   preserving the exact product packaging, label, proportions, and colors. Use
   `nano_banana_generate` only when a new scene is required.
4. Animate that finished still with `fal_image_to_video(model="wan")`. Describe the
   reference motion and explicitly preserve product identity and composition.
5. Save one MP4 under `artifacts/`, verify it is non-empty and playable, and stop.

If the reference page is unavailable, use the user-provided screenshot or description
and continue. Do not crawl Instagram, call Shopify APIs, inspect a rendered DOM, or keep
trying browser extraction after the first failure.

## From-scratch workflow

When the user does not provide a finished image or wants a wholly new scene:

1. Generate one keyframe with `nano_banana_generate` when product identity or exact
   composition matters.
2. Use `gemini_veo_generate(model="veo-fast")` for a normal from-scratch video, or
   `model="veo"` when premium fidelity/native audio is explicitly needed. Use Fal Wan
   text-to-video when low cost and speed are the priority.
3. Save and verify one final MP4. Do not generate separate cinematic clips unless the
   user requested multiple shots.

## Video editing workflow

Use this section whenever the user supplies clips or asks to stitch, trim, resize,
reformat, add transitions, replace/mix audio, add captions, add a logo, or otherwise
adjust an existing video.

1. Inspect every input once with `ffprobe` and record duration, frame rate, dimensions,
   pixel format, audio streams, and rotation metadata. Confirm that each file is a
   playable video before editing.
2. Decide the smallest edit graph that satisfies the request. Do not regenerate clips
   that can be edited locally.
3. Use FFmpeg as the default production editor:
   - trim or extract: `-ss`, `-to`/`-t`, with stream-copy only when codec boundaries are
     safe; otherwise re-encode;
   - normalize clips before stitching: H.264, yuv420p, consistent frame rate, dimensions,
     time base, and AAC audio;
   - stitch compatible clips with the concat demuxer; use `filter_complex` when crossfades,
     fades, overlays, scaling, or audio mixing are required;
   - reframe with `scale` plus `crop`/`pad` and preserve the requested aspect ratio;
   - add captions or brand marks with a verified local font/file and `drawtext` or an
     image overlay; never invent a logo or silently substitute a font;
   - mix or replace audio with explicit `-map`, `amix`, volume, fades, and a deliberate
     AAC output stream. Preserve source audio unless the user requests replacement.
4. Use other local production tools only when they are already available and materially
   simplify the requested edit. Prefer an existing Remotion composition for data-driven
   motion graphics or repeated format variants; use ImageMagick only for raster asset
   preparation; use `mediainfo` only as an additional inspection aid. Do not install a
   new editing framework for a one-off trim or stitch without user approval.
5. Render to a temporary path, inspect the result with `ffprobe`, and atomically move or
   copy the verified result to the final artifact path. Never call an unverified partial
   render the final deliverable.

### Editing templates

Use these as patterns, adapting paths and values rather than blindly copying them:

```bash
# Inspect
ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name,width,height,r_frame_rate,pix_fmt,channels -of json input.mp4

# Normalize one clip for later stitching
ffmpeg -y -i input.mp4 -vf "scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2" \
  -r 30 -c:v libx264 -pix_fmt yuv420p -c:a aac -ar 48000 -ac 2 normalized.mp4

# Stitch normalized clips
ffmpeg -y -f concat -safe 0 -i concat.txt -c copy stitched.mp4
```

For crossfades, overlays, captions, or mixed audio, use `filter_complex` and re-encode
instead of forcing stream-copy. Keep all intermediate files in the task artifact
directory and use explicit filenames; never create nested paths such as
`artifacts/artifacts/...`.

## Hard limits and validation

- Maximum: one reference inspection, one product-image retrieval plus one fallback, one
  keyframe, one video generation, and one deliberate provider fallback.
- Use FFmpeg and other production-grade local tools when the user requests editing or
  when a generated clip must be normalized for a requested final format. Do not add
  optional branding or effects that were not requested, and never let optional polish
  block delivery.
- Put working files and the final file under `artifacts/video/<slug>/` or `artifacts/`;
  never leave the final media in the repository root.
- Before claiming success, verify the MP4 exists, has non-zero size, and `ffprobe`
  reports a playable video stream, positive duration, expected dimensions, and the
  promised audio stream. Report failures exactly.
- Stop as soon as the verified MP4 exists.
